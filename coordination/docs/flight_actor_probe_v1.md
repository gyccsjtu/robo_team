# 实体视觉飞行开发用例 v1（2026-10-03 冻结）

在现有六机开发用例中启用`--flight-actor-probe --flight-seconds 120`。初始world仍为经过出生净空检查的空场景或六箱场景；六机全部升至3.5m以上后，开发场景生成器通过Gazebo factory插入原仓库actor_0。生成器仅用独立观察数据检查插入位置与每架飞机水平距离至少10m，避免测试自身在机体内生成模型；该观察不发送给manager/agent，不作为发现或分配目标的输入。保存初始world、实际插入SDF、原actor来源、请求与哈希，不能称作原始官方场景运行。

actor保留原skin/动画/插件，开发位置与行走边界单独设置，使用原ActorMotion控制一次短距离行走。初始world出生证明不包含后插入动态模型，不构成动态场景三维安全证明。实体人物接触/完整碰撞仍缺证，必须ABSTAIN；formal_competition_pass=false。此接口只冻结开发用例，不扩大正式规则允许的输入范围。

软件渲染时，六机连接完成后调用Gazebo物理服务，将开发物理步进更新率从250降至50Hz，步长仍为0.004s，保存development_physics_rate.json。原相机/雷达频率和模型参数不变。不可直接在world里将初始化更新率改为50Hz：PX4插件加载时会拒绝；run03已保存该失败。该用例更慢，60秒仿真约需5分钟墙钟，120秒约需10分钟；自有进程设有总墙钟上限，超时不能判通过。

run01/run02失败（六路图像过期、无目标执行证据），run03启动失败。run04/run05实际完成60/120秒演员执行观察，但逐行复核发现并发记录损坏，原报告保留，followup_stream_audit.json否定完整执行证据。后续记录器加锁并在退出后审计每行，缺失/损坏判失败。通过还要求相同目标代次运动命令覆盖的时间段内，该机真实水平位移超过0.5m；后来搜索任务的运动不能借作目标执行证据。

六个实际perception节点消费未改参数的原相机与CameraInfo；实际桥转发原图schema2证据，实际manager/agent经v2.1复验。任何目标真值只进入观察记录。通过需要：真实视觉与确认消息、目标任务实际授权、相同代次的路线授权、该代次后实际运动命令，以及现有六机雷达轨迹/净空观察通过。单纯像素命中、登记目标、日志声称跟踪、超时退出均不足。没有官方裁判反馈时不检验/宣称15s消除成功。
