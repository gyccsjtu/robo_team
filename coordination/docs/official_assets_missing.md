# 待接入的赛项方资源

赛事规范中的两个网址已经用于搭建环境：公共 XTDrone 仓库和 XTDrone 中文安装文档。它们不是无法访问，也不是等待项。当前单机开发基线可用于起飞、控制、传感器和避障训练。

以下内容通常需要在赛项方发布后接入；它们是最终比赛集成项，而不是当前开发阻塞项：

| 优先级 | 待接入内容 | 必须记录的证据 | 影响范围 |
|---|---|---|---|
| P0（发布后） | 最终比赛 world、障碍布局、随机化规则与六机 launch | 下载地址、版本/commit、SHA-256、许可证 | 最终场景适配与性能验收 |
| P0（发布后） | 裁判节点、消息包和接口契约 | topic/service/action、消息字段、频率、坐标系、允许订阅范围 | 计分、开始/结束、目标上报 |
| P0（若提供） | 赛项专用 Docker 镜像或离线 tar | image 名称、RepoDigest、tar SHA-256、导入命令、许可证 | 替换当前开发镜像进行最终冻结 |
| P1 | 传感器清单、计价和模型参数限制 | SDF/URDF 参数、安装位置、算力限制 | 合规传感器配置 |
| P1 | 三次连续尝试、复位与随机种子流程 | 可执行步骤和裁判信号 | 赛场运行自动化 |
| P1 | GPU/网络/挂载限制 | 驱动/CUDA、`--gpus`、联网和持久化规则 | 最终部署参数 |

## 接入原则

1. 不以历史 `ego_planner.zip`、旧控制脚本或自行猜测的话题替代赛项方资源。
2. 资源放在源码树外，容器中优先只读挂载；大模型和比赛镜像 tar 不提交。
3. 新镜像通过 `.env` 中 `ROBOCUP_OFFICIAL_IMAGE` 替换，不重写工程结构。
4. 收到后立即补充 `docs/version_manifest.md` 和本文件，再运行官方入口的 build/start/health check。
