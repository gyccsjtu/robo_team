# 在线雷达规划 v1（开发接口与验证边界）

`ONLINE_RADAR_PLANNING=1` 将实际 agent 的候选路径规划切换为在线射线观测地图；未知及3s过期观测阻挡规划。地图取一次不可变快照，膨胀机体净空，再阻挡友机实测位置及保留路线。终点尚不可达时只向当前已观测、连通的可达前沿推进，保留原任务目标；不能将到达前沿当成到达任务目标。4邻接A*不使用未知区域直飞兜底。任务代次和规划请求号均验证后，实际路线获manager授权才提交。

最后速度发布检查在线地图 epoch 与采样时效（1.5s）、停止段净空，同时受任务、路线、雷达与机队保护。地图变换变化使旧地图失效。在线地图是水平投影，尚未处理姿态/高度分层，不能证明完整三维自由体积。

雷达近场盲区的起飞初始化仅用于隔离空场景：`RADAR_START_CLEARANCE_FILE` 的 schema_version=1、run_id、world_path、world_sha256、positions须对应本轮文件及逐机起点；加载器只接受ground_plane/sun、无model/actor的world。它提供起点2m开发净空补丁，不能用于未知随机赛场。随后只保留当前机体1.2m足迹下曾证明自由的格，新未知格不加入，实际命中撤销。没有此初始化证据时在线模式拒绝启动；默认旧模式仍需显式迁移。

在线manager现只读取metadata边界，不使用存储障碍过滤、临楼奖励或存储LOS；关闭以量程圆盘推定覆盖的NBV模式。agent启动时地图全部阻挡，规划以真实射线地图驱动，LOS也不能读取旧障碍布局。任务点仍可能未知；可飞证明由在线规划提供，任务覆盖和不可达任务接替仍需完善。

开发起飞证据schema2还支持已验证静态轴对齐箱体：仅单link、单box碰撞、零旋转、无动态actor/joint/plugin，起点2m补丁须与每个箱体的水平投影严格分离。接触观测插件只允许Gazebo bumper。此验证只初始化出生点，不把箱体坐标输入规划器；world文件仅独立观察器用来核对真实轨迹净空，比赛地图不能套用此开发证明。

非空场景run14在六个3×3×10m箱体中运行真实六机60.1s，六机执行实际预约路线、均有真实占据观测，最小采样间距7.4776m、最大高度5.1861m、最小箱体表面水平距离1.4333m。六路箱体接触观察新鲜，机体接触0；声呐探测锥与箱体相交14725次，单独分类并保存原始记录。开发观察门槛通过；机间/地面全部接触证据及正式比赛仍未验收。见 `validation/six_obstacles_run14/`。
