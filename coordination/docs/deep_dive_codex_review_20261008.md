1. **输出不重叠不是强制串行的证明。** yolo_target_bridge.py TargetBridgeCore.tick遍历所有tracks，_tick逐个_emit，不是全局只选一个目标。构造green/blue各3条0.95观测后tick(1.25)同时输出两色；只是结构检查，非实体成功。真实authority_events按TASK_GRANTED与STOP/退役重建有效任务，确实本轮最多一个target；但要继续对齐同刻已有候选/confirmed输入、manager拒绝/忙机/占用，才能归因。109/191秒是不同目标上报段间空档，不是已证明的调度切换延迟。不能按两段空档外推五次必需切换、宣称精度修好也必然不可能600秒6/6。

2. **零track_publish是感知发布为零，不是运动放行或追踪任务为零。** 原生轨迹证明uav_1/3/5相对起点最大位移64.34/53.66/61.36米；这些飞机没有target授权记录（其任务为search）。一个uav_1蓝色拒绝行不能证明三机都被同一蓝色目标占用。需分别按机号、不同image_stamp、颜色、拒绝原因和授权任务统计；同一旧图的track_reject循环不算多个不同帧。blue0是perception_real.py在track_reject行构造的诊断字符串，合法visual wire仍是blue，桥映射t1；它不是接口词表突然变更。

3. **陈旧内部状态是既有保留策略。** COAST_TIME=1.5限制官方上报新鲜性；DROP_TIME默认6秒用于内部保留/接替窗口，tick在超过DROP_TIME后清alive。age2.6–5.6秒的stale skip并不证明超过生命周期或旧坐标上传；无需为这个预期拒绝新开短轮或直接删状态/释放占用。

4. **发布中位间隔0.1不能排除连续性问题。** green有30.4秒断流，red有2秒间隔，它们都会影响15秒窗口；0.3%/1.6%的稀有断点仍可决定成败。正确结论是活跃段典型频率足够，准确性是已观察的重要阻塞，连续性和覆盖仍未完全解决。“峰值1.74Hz”其实124/71.1的跨度平均，不是峰值。122.7秒是几段首尾跨度之和，包含内部长空档，不能当作真实连续活跃占用率。
