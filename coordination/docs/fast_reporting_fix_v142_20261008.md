# v1.42：官方上报来源隔离

## 问题、方案和完成范围

已确认：同色全局融合用另一架尚未近距确认的飞机的新原图更新t_obs，原近距来源虽仍新鲜并ready，却不能给这个较新的全局坐标授权。旧出口因此拒发。修法不是删除时间匹配门，而是使官方坐标与近距资格始终来自同一架飞机。

已实现独立纯Python OfficialReportSources。每个颜色/来源使用现有TargetBridgeCore及其激活、速度补偿和坐标跳变检查；内部全局融合完全保留。官方选择新鲜合格来源，保持当前来源直至失效，才换到另一个已合格来源。来源轨迹最新原图必须与该来源许可最新原图完全一致，拒绝借较新许可上传被该来源轨迹拒绝后的旧坐标。重复原图不能激活，已消除槽不能复活，多颜色可同时输出。白色人体证明、近距三图及原图1秒要求保留。

不新增run脚本，不改变官方裁判/人物、传感器、速度、高度或路线占用。此次没有启动新仿真，也没有改WorkBuddy的渲染环境。该改动只修已证实的桥侧断流原因，不宣称修好所有漏检、坐标离群和搜索覆盖不足。

## 验证与局限

回放读取归档accepted，不重新模拟完整ROS回调、red槽关联和裁判；它不能证明坐标小于1米或连续15秒，更不能据此声称6/6。单来源补偿减少跨相机混用，但其实体精度和换机跳变仍需实际验证。

边界测试覆盖远距新来源不污染近距上报、重复图、v2/导航候选禁止官方输出、失效图、来源自身拒绝、白色人体证明、来源换机、已消除不复活、不同颜色并发及真实桥timer仅上传一次。修订旧测试夹具以初始化此前新增的诊断统计，并让方法提取测试调用新拆出的_emit_actor；不修改旧限时/红色传输断言。
