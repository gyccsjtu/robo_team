# 移除旧人物出生点的默认搜索偏置

## 现场依据与修复计划

当前第二轮仍执行e06c20d，不能用新候选解释本轮结果。只读核查manager进程环境未设置PRIORITY_CORNER，执行快照swarm_task.py默认启用该开关，并默认PRIORITY_POINTS=-35,-28。源码注释明确说明来自旧actor_5出生点。其60分偏置与普通约4分的效用不在一个量级。

第一轮拍卖1941.908秒的原始日志：uav_1分配(-32.5,-28.5)，效用59.208191；uav_2分配(-18.5,-42.5)，效用20.348441；其他四架效用4.58至4.70。这证明旧先验确实进入本轮任务选择。不能据此把所有未发现、低速或最终结果归因于该偏置。

修复范围：

1. 通用分配器默认关闭地点优先级，默认地点列表为空。若外部开发用途显式配置合法搜索优先点，仍可使用已有选择算法；不再隐含人物出生坐标。
2. 比赛city入口显式关闭PRIORITY_CORNER，避免父进程旧环境恢复偏置。现有区域、拍卖效用、视觉证据、STOP、占用及路线门不变，不把真值输入控制。
3. 离线核查默认无点、显式开关但无点、显式自定义地点及city环境覆盖。以实际TaskAllocator分配检查默认行为不受旧坐标吸引。此变更不需修改线上schema。
4. 当前轮不重启、不改快照。它结束后将新候选与蓝色身份确认、搜索回访证据一起评估，按新的实体问题决定下一轮。

这修复的是不符合未知人物搜索目标的默认先验，不证明搜索覆盖、目标识别或6/6已经完成。
