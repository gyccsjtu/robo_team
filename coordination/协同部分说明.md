# RoboCup 集群协同搜索 —— 协同部分详细说明

> 适用工程：ROS Noetic + Gazebo 11 + PX4 SITL，6 架 `typhoon_h480`，搜索并"消除"6 名地面恐怖分子（actor）。
> 本文全部内容取自协同层真实源码，关键逻辑后附代码行号链接，便于追溯。

---

## 1. 协同层要解决什么问题

比赛任务：在有限时间、含建筑遮挡的城市场地中，用多旋翼无人机**自主起飞 → 区域覆盖搜索 → 发现目标 → 绕目标持续观测 15 秒 → 官方裁判判定"消除"**。

由此协同层必须处理四件事：

1. **"谁去哪"**：把场地切成搜索格，分给不同无人机，避免重复扫、漏扫（任务分配）。
2. **"怎么去不撞"**：沿绕开建筑的路径飞行，并在执行层做近障兜底（路径规划 + 避障）。
3. **"看到了怎么确认"**：对目标做连续 15 秒、坐标误差 <1m 的稳定观测（协同追踪 + 多源融合）。
4. **"队友之间怎么不互撞"**：多机同场的实时避碰（ORCA 风格）。

## 2. 总体架构：集中式分配 + 分布式执行

协同层采用**"一个大脑 + 多个手脚"**的混合架构：

```
                         官方裁判 (score_cal)
                   /left_actors   /find_actor_0..5
                          │  ▲
                          ▼  │
  6× perception_real ── /coordination/target_report ──▶ yolo_target_bridge
   (YOLO 检测, 合法)                                      │
                                                  /swarm/target_states
                                                          │
                            ┌─────────────────────────────┼──────────────┐
                            ▼                             ▼              ▼
                     swarm_manager ── /swarm/assignment (广播任务) ──▶ 6× swarm_agent
                     (唯一的集中"大脑")   /swarm/finish                   (每架机一个)
                            ▲                             │              │
                            └──────── /swarm/uav_status ──┘              │
                                        /swarm/detection                 │
                                                                         ▼
                                                    MAVROS → PX4 → Gazebo
```

- **集中式**：只有 [swarm_manager.py](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_manager.py) 做任务分配与全局调度，单点决策、逻辑清晰。
- **分布式**：每架机的 [swarm_agent.py](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py) 自主完成路径跟踪、避障、避碰，管理器掉线时飞机仍能安全飞行/悬停。
- **数据来源合法**：目标位置只能来自己方 YOLO，经 [yolo_target_bridge.py](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/yolo_target_bridge.py) 转发，正式比赛禁止订阅 Gazebo 真值（规则 §2.5.11）。

## 5. 任务分配：集中式拍卖

分配逻辑内核在 [swarm_task.py](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_task.py)，管理器每 `ALLOC_PERIOD=2s` 调一次。

### 5.1 覆盖栅格 CoverageGrid

- 场地按 `GRID_SIZE_M=7.0m` 切成搜索格（batch 实测 7m 优于 10m：中位完赛 157.5s vs 286.1s），见 [swarm_task.py L24](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_task.py#L24)。
- 每格四态：`FREE(未分配) / ASSIGNED(执行中) / COVERED(已覆盖) / REVIEW(需复查)`。
- 搜索边界优先取元数据 `bounds`（对齐官方 actor 真实活动范围），读不到才退回硬编码 ±100/±50，见 [_search_bounds L170-L190](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_manager.py#L170-L190)。

### 5.2 区域分割（静态责任区）

建图时按"蛇形轮流"把格分给 6 个责任区，相邻格落在不同区，天然利于分散，见 [_compute_zones L126-L139](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_task.py#L126-L139)。

### 5.3 拍卖效用函数

每架机对每个候选格计算一个效用，管理器按"各机取剩余格中自身效用最高者"贪心分配，**已选格即时移出候选池**（轻量拍卖、保证不重复），见 [TaskAllocator.utility L349-L439](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_task.py#L349-L439)：

```
U(i,c) = w1·未搜索收益
       + w_novelty·新颖性            # 越久没被派过分越高（面覆盖主排序键）
       - w_flight·预计飞行时间        # 距离/巡航速度，超过 FLIGHT_CAP 封顶
       - w_overlap·与他机重复率
       - w_risk·路径风险
       + w_balance·任务均衡
       - w_distance·机间距离惩罚
       + w_zone·区域责任
       + w_edge·临楼偏置             # actor 多贴建筑出生
       + w_spread·分散奖励
       + w_vis·LOS-NBV 可见增益      # 动态：看过/别机承诺的立刻贬值
```

其中两个关键设计：

- **新颖性（novelty）**：按"该格距上次被派的时间"打分，是保证**面覆盖**（而不是总在脚下打转）的主排序键。
- **LOS 感知 NBV（next-best-view）**：管理器启动时预计算"从每个视点能 LOS 看见哪些格"，派单时调 `commit_visible` **立即把可见集标记为"已承诺"**——这是一种次模贪心，别的机再看同一片区域增益≈0，队形自动散开，见 [_build_visibility L420-L451](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_manager.py#L420-L451) 与 [commit_visible L272-L287](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_task.py#L272-L287)。

### 5.4 任务租约 LeaseManager

防止某架机掉线/卡死把格子永久占住，见 [LeaseManager L546-L584](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_task.py#L546-L584)：

- 派单即授租约，时长 = 飞行时间×1.5 + 10s 缓冲（自适应）。
- agent 持续上报 → `renew` 续租；超时未续 → `expire` 把格退回 `FREE` 重新拍卖。

### 5.5 楼边修复（消除"永久黑洞"）

早期用"格中心是否在建筑内"判可达，整格被压中就永久 `COVERED`，形成搜索黑洞。现改为：格中心不可达时，在格内按 `WAYPOINT_RING=(2,3.5,5m)` 环上找一个**可达替代航点**，只有整格都无可达点才判死；同时计算"临楼度"喂给拍卖，见 [_find_blocked_cells L280-L351](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_manager.py#L280-L351)。

## 6. 单机 Agent：状态机与控制流

agent 主循环 [run() L1784-L1814](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1784-L1814)：

```
等 MAVROS 连接 → 等 local_position 就绪 → 标定局部→世界 offset
→ 配置 FCU → 预热/切 OFFBOARD/解锁
→ 循环(20Hz): _control() + _detect_targets() + 周期发 UavStatus
```

### 6.1 坐标与 offset

- agent 只用轻量高频的 MAVROS `local_position/pose`；世界坐标 = 局部坐标 + 恒定 offset。
- offset 由启动脚本通过私有参数 `~world_offset_x/y` 注入（= 该机起飞世界坐标），属合规路径，**不再订阅** `/gazebo/model_states`，见 [_calibrate_offset L422-L460](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L422-L460)。

### 6.2 起飞：预热 → OFFBOARD → 解锁

见 [_arm_and_offboard L619-L706](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L619-L706)，关键时序：

1. 等 EKF 稳定（连续 `STABLE_NEEDED=40` 次 20Hz 采样、z 在出生点附近）。
2. 持续发**纯零速**（`vz=0`）预热，让 OFFBOARD setpoint 生效——带爬升速度会被 PX4 拒。
3. 切 OFFBOARD、解锁都**无限重试直到成功**（多机 SITL 下 EKF 就绪时间不定），重试间隙继续发零速。
4. 重启协同时若飞机已在空中 OFFBOARD（z>1m），直接跳过起飞等待。

### 6.3 爬升门（修"趴地起飞"）

解锁后、高度未到 `CLIMB_DONE_ALT=2.5m` 前，**无论派到什么任务都只垂直爬升、水平速度锁零**，避免地面上就发大水平速度导致大倾角、升力垂直分量不足而贴地滑行，见 [_control L1163-L1173](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1163-L1173)。

### 6.4 控制状态机 `_control()`

见 [_control L1144-L1284](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1144-L1284)：

```
降落中?            → 持续 vz=-1 下降，触地解锁
未过爬升门?        → 只垂直爬升
world_xy 无效?     → 悬停
无 assignment?     → 清路径/盘旋，悬停
task_type=1 追踪?
   距目标 < ORBIT_RADIUS → 进入盘旋 _fly_orbit
   否则 → A* 异步规划飞向目标；近 SPOOK_DIST 压速
task_type=0 搜索?
   已在盘旋 → _fly_orbit
   到达格中心(<ARRIVE_TOL) → _check_start_orbit 看能否就近视目标盘旋
   否则 → A* 沿路径飞；已知目标在附近提前压速；友机避碰
```

### 6.5 目标追踪接近（task_type=1）

- 目标位置随 manager 约 5Hz 重发刷新；**同一目标只静默更新位置，不重置盘旋、不触发重规划风暴**，见 [_assign_cb L513-L527](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L513-L527)。
- 对移动目标做 A* **重规划节流**：目标移动 >`TRACK_REPLAN_MOVE=3m` 且距上次规划 >`TRACK_REPLAN_SEC=2s` 才重算。
- **近距压速**：距目标 <`SPOOK_DIST=22m` 时限速 `SPOOK_SPEED=0.8m/s`（<官方 1.0m/s 逃跑阈值、提前 2m 保险），防止冲入 20m 触发 actor 逃跑。

### 6.6 盘旋确认 `_fly_orbit()`

见 [_fly_orbit L1474-L1549](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1474-L1549)：

- 绕目标做圆周：`ORBIT_RADIUS=8m`（匹配 actor 安全半径 7m）、`ORBIT_SPEED=0.12rad/s`（线速 0.96m/s <1.0）。
- 每帧用目标最新位置更新盘旋中心，P 控制飞向圆周点。
- **偏航持续对准目标**：盘旋全程 `_look_at=(tx,ty)`，机头角速度 P 控制（`YAW_KP=2.5`、限幅 1.5rad/s），修"盘旋时目标甩出水平相机 ±45° 视场"的问题，见 [_send_vel L901-L914](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L901-L914)。
- 目标长时间（`TARGET_STALE=2s`）无位置更新 = 已被官方删除 → 终止盘旋，防对空盘旋。
- 满 15s 后若官方在 `ORBIT_GIVEUP=30s` 内仍未消除（链路断/目标逃跑），放弃并进入 `GIVEUP_COOLDOWN=45s` 冷却，把飞机释放回搜索，避免被死锁（曾有单机被占 571s）。

### 6.7 防扎堆：认领机制

开始盘旋的 agent 通过 `/swarm/orbit_claim` 广播认领；其它机在 `CLAIM_FRESH=3s` 内看到该目标已被认领就不再抢，见 [_publish_claim L1378-L1390](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1378-L1390) 与 [_claimed_by_other L1391-L1402](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1391-L1402)。

## 7. 路径规划：异步 A* + 平滑 + 跟踪

### 7.1 为什么 A* 要异步

全图 A*（栅格约 380×260、分辨率 0.5m）实测耗时 27~74ms，塞进 20Hz 控制循环会阻塞 1.5~3 个周期，追踪 5Hz 重发时把循环拖到 20Hz 以下，PX4 判 offboard setpoint 丢失 → failsafe。因此改为**后台守护线程**：主循环只投递请求、立即继续发速度，规划完成后原子提交路径，见 [_planner_loop L1059-L1087](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1059-L1087)。新请求会覆盖旧请求（合并），路径未就绪时 `_stream_last_v` 续发上一次速度，**指令永不中断**。

### 7.2 A* 本身

见 [plan L178-L248](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_navigation/src/robocup_navigation/astar.py#L178-L248)：

- 8 连通、对角代价 √2，启发式为 octile 距离。
- **防切角**（`prevent_corner_cutting`）：对角移动要求两个正交邻格都自由，否则不允许——防止从墙角斜插过去。
- 失败原因细分：`START/GOAL_OCCUPIED`、`START/GOAL_OUT_OF_BOUNDS`、`NO_PATH`、`EXPANSION_LIMIT`。
- 障碍在飞行前用 `INFLATE_M=0.5m` 圆盘膨胀，路径与墙保持安全距离（覆盖旋翼半径+裕度），见 [inflate_grid L241-L263](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L241-L263)。

### 7.3 规划失败的恢复链

见 [_compute_plan L1004-L1052](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1004-L1052)：

1. `START_OCCUPIED` → 用 `_nearest_free_cell` 找最近自由格重试。
2. `PLAN_FALLBACK=0`（默认）：仍失败则**不移动、等下周期**，绝不直飞穿楼。
3. 需要旧实验行为时才显式 `PLAN_FALLBACK=1` 退化为直飞（当前地图含建筑，会把一次规划失败升级为撞楼，故默认关闭）。

### 7.4 平滑与路径跟踪

- A* 折线经 Catmull-Rom 样条平滑为连续可跟踪轨迹，见 [smooth_path L266-L286](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L266-L286)。
- 跟踪用**前瞻点**：`LOOKAHEAD=3m`（>刹停距离 v²/2a=2.25m），对前瞻点做 P 控制（`POS_KP=0.8`），见 [_pick_local_goal L1121-L1143](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1121-L1143)。

## 8. 避障体系（多层纵深防御）

> 核心教训：**碰撞约束必须放在执行层，不能只靠规划层**——规划失败续发、追逃跑演员贴墙、冲出边界等情况，规划层管不到。

| 层级 | 机制 | 依赖 | 作用 |
|---|---|---|---|
| 规划层 | A* 绕障 + 0.5m 膨胀 | 地图栅格 | 从源头绕开建筑 |
| 反应层 | 栅格近障保护 `_grid_guard_velocity` | 地图栅格（**不需激光**） | 每帧速度前瞻，转向/刹停 |
| 反应层 | 雷达近障保护 `_radar_guard_velocity` | `/scan` 激光 | 有激光时按真实回波修速 |
| 多机层 | 友机避碰 `_apply_friend_avoidance` | 友机位置广播 | 防机间互撞 |

### 8.1 栅格反应式保护（无激光兜底）

见 [_grid_guard_velocity L810-L863](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L810-L863)：

1. 沿当前速度方向，按 0.5m 步长前瞻到**刹停距离** `v²/(2a)+0.4m`（5m/s 时约 5.4m）。
2. 任一点被占（障碍或**越界**，越界也当墙，防冲出地图）→ 从偏 15° 起步、左右各方向搜索自由扇区，把速度转向自由方向。
3. 左右各搜到 120° 都不自由 → **直接刹停**（v=0）。
4. 起飞爬升阶段水平速度≈0（<0.05 直接放行），不会误触发。

### 8.2 雷达保护（有激光时）

有 `/scan` 且数据新鲜（`RADAR_FRESH_S=0.5s`）时，按前/左/右近距回波，在 `RADAR_WARN_R=4m` 减速、`RADAR_STOP_R=1.2m` 停，见 [_radar_guard_velocity L752-L803](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L752-L803)。两道保护在 [_send_vel L871-L874](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L871-L874) 串联，雷达在线时双保险。

### 8.3 友机避碰（ORCA 风格）

见 [_apply_friend_avoidance L1589-L1743](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_agent.py#L1589-L1743)：

- 用**三维距离**（高度差也计入，`SAFE_3D=4m`）判断是否需要避让。
- 构建 ORCA 半平面，在全向 16 个候选方向中选代价最小者；`SEP_CAP_FRAC=0.8` 保证半平面在 `MAX_SPEED` 内数学上有解。
- **对称死锁**用机号奇偶做 tie-break（奇数偏右、偶数偏左）。
- ORCA 无解时退回纯排斥，保证兜底。
- 起飞/爬升阶段（z < `ALT_TAKEOFF+CLIMB_NO_AVOID=3m`）豁免水平避让——起飞区 6 机间距仅约 8m，不豁免会全部互斥死锁、谁也起不来。

## 9. 协同追踪与多源融合

管理器确认/消除目标的核心是 [CooperativeTracker](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/cooperative_tracker.py)。

### 9.1 官方"三门槛"（规则5）

连续 15 秒确认必须**三条同时满足，断一条即清零**，见 [update L234-L284](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/cooperative_tracker.py#L234-L284)：

| 门槛 | 阈值 | 含义 |
|---|---|---|
| (a) 坐标误差 | `< ERR_TOL=1.0m` | 每次上报坐标 vs actor 真值 |
| (b) 上报间隔 | `≤ GAP_TOL=1.0s` | 相邻两次合格上报不能断档 |
| (c) 连续时长 | `≥ CONFIRM_TIME=15s` | 累计满 15 秒 |

不满足 → 发 `reset` 事件、`confirm_since` 清零重来。真实链路里目标被官方多次重置（曾有 t2 被重置 9 次、拖到 306s），只有能复现"被重置"，调度决策才有意义。

### 9.2 多源 + 时间融合

- **空间融合**：多机同时看见时按 `1/σ²` 加权（独立噪声下 σ→σ/√N）。
- **时间融合**：叠加 alpha-beta 常速度滤波；**自适应 beta**——目标移动时增大 beta 抑制滞后、静止时减小 beta 狠压抖动，见 [_beta_for_speed L77-L86](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/cooperative_tracker.py#L77-L86)。
- **不做 lead pursuit**（按速度外推未来再上报）：裁判比的是"上报 vs 当前真值"，外推只会单方面增大误差；滞后应靠加大 beta 治本（离线蒙特卡洛已验证）。

### 9.3 规则4：30s 未消除 → 瞬移

目标自"首次合格上报"起墙钟满 `EVADE_TIME=30s`（可用 `TELEPORT_INTERVAL` 覆盖）仍未消除 → 发 `evade` 事件，目标瞬移躲藏、所有计时清零。注意是**墙钟跨度**，不受确认计时反复重置影响，且事件只触发一次，见 [update L275-L283](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/cooperative_tracker.py#L275-L283)。

### 9.4 确认期冗余派机

只派一架机确认会因视线遮挡/抖动反复重置。管理器按**重置次数或确认进度卡住**定向增派（默认重置≥2 次、或进度停滞≥`BACKUP_AFTER=12s`），且备份机上限 2 架、距离 >`BACKUP_MAX_DIST=60m` 不派（飞过去比等还久），见 [_dispatch_backup L739-L812](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/swarm_manager.py#L739-L812) 与 [needs_backup L379-L398](file:///home/gycc/桌面/RoboCup_Team/coordination/src/robocup_swarm/scripts/cooperative_tracker.py#L379-L398)。备份机同样必须登记为 observer，否则其观测会被忽略。

## 13. 一次完整任务时序

```
① run_match start：起 Gazebo/PX4/通信桥/裁判/6×感知/桥/manager/6×agent
② agent：等连接 → 标定 offset → 预热发零速
③ agent：切 OFFBOARD(无限重试) → 解锁(无限重试)
④ agent：水平锁零，垂直爬升到 2.5m（爬升门）
⑤ manager：拍卖分配搜索格 → 广播 SearchAssignment(task_type=0)
⑥ agent：异步 A* 出路径 → Catmull-Rom 平滑 → P 控制沿路径飞
   （全程：栅格/雷达反应式保护 + 友机 ORCA + 高度护栏）
⑦ 某机 YOLO 看到 actor → perception 发 target_report
   → bridge 融合/转发 target_states
⑧ agent：20m+LOS 几何门通过 → 发 detection；manager 派追踪(task_type=1)
⑨ agent：接近至 8m，压速 0.8m/s → 绕目标 8m 盘旋，机头持续对人
⑩ 连续 15s 合格上报（误差<1m、间隔≤1s）→ 官方判 actor OK、移出场地
   → /left_actors 更新 → manager 释放该机回搜索
⑪ 6 名 actor 全部消除 → 任务结束
   （中途：30s 未消除 actor 瞬移；确认受阻则定向加派备份机；
    找漏则重开覆盖格继续巡逻）
```

## 15. 合规性要点

- **目标只从己方 YOLO 获取**：`perception → target_report → yolo_target_bridge → target_states`，全链路不碰 Gazebo 真值。
- 启动脚本在起协同层前强制 `SEED_TRUTH=0`，杜绝"上帝视角"播种。
- agent 只订阅轻量 MAVROS 话题与协同话题；offset 由参数注入，不订阅 `/gazebo/model_states`。
- 高度严格压在 6m 红线以下（硬顶 5.2m，多重护栏）。
