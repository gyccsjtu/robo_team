# 红色坐标匹配口径（2026-10-03）

2026-10-04接入修正：核查发现manager/bridge已使用“任一红色仍在场”的判断，但agent的`_left_actors_cb`仍将t4/t5误当官方身份。实飞先消除actor_5后，剩余红人被视觉重新分配为red1/t5，agent会被每条剩余清单反复清掉该观测并永久冷却。现agent同步使用`actor_slot_remaining`：只有两位红色都消除后才清两槽；普通颜色仍逐个按官方ID消除。两个实际agent回调回归覆盖保留与清空，尚待下一轮实飞。

来源：用户本日转述赛事组对两个相同红衣人模型缺陷的处理：只上报红色与坐标，裁判与两个红衣人真值比较，匹配其中一个即可累计该人的消除判据。此处不是声称已有公开新版裁判，也不以本地旧脚本的固定 red1→actor_5、red2→actor_4 覆盖赛事组口径。

对外统一 `/actor_red_info` 的 ActorInfo，cls=red。每个几何轨迹分别上报坐标；不向两条固定身份话题重复广播猜测身份。判据的1m严格误差门槛、连续15s与原裁判的数据间隔检查保持原实现。开发裁判副本选择距离最近、误差严格小于1m的剩余红衣人，每条消息最多匹配一人，不重置另一人的确认窗口。没有匹配的上报不延长有效观测，原裁判的间隔检查仍会使断流失败。

`red_judge_compat.py` 仅适配独立scene内副本，原始官方源码不改。scene_manifest记录原始及适配后SHA、适配原因、来源；该副本是依据用户提供口径的开发实现，正式裁判最新实现仍需赛事组发布或确认。

确认观测消息schema_version=2不加字段，但红色target_id语义修订：red1/red2为集中桥分配的几何轨迹槽，不再声明官方actor下标。生产桥按位置和原图时间关联两槽；同一人跨相机合并，两人位置不同则分槽。六机任务仍各持唯一目标锁。manager和bridge在官方仅消除一个红衣人时不据槽号猜测另一轨迹已消除；消失轨迹依原有观测失效/停稳接替流程处理，两人均消除后才能明确清空两槽。旧依赖固定actor编号的接入需同步更新remaining判断；新生产入口已更新。

轨迹交叉、遮挡或瞬移仍可能造成关联断流，该实现不宣称视觉身份可区分。真值仅在裁判和独立审计节点中读取，不传给参赛控制。独立红色误差审计也改为对两人分别对齐原图时间后取最小误差；旧“只对actor_5”的72m诊断不再当作新口径下的定位错误结论。
