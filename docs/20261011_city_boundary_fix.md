# 场地边界、搜索范围与制动修复

## 证据与验收状态

上一轮 `logs_20261011_140634` 实际运行 `f4c5df4`，官方六人完成时间
510.348 秒，但发生飞出城市边框，不能作为安全验收通过。
3 号曾到 `(134.10,54.57)`，4 号曾到 `y=57.27`。本地官方
`XTDrone/robocup/map_generator.py:383–409` 生成的边框为
`x[-50,130], y[-50,50]`。此前飞控误用了人物插件的
`x[-50,150], y[-60,60]` 范围，管理器又把空图的传感器缓冲区
`x[-55,155], y[-65,65]` 全部作为搜索任务。日志实际派过
`y=57.5/64.5` 的搜索格。

这里采用本地地图生成器的城市边框作为队伍飞行限制；不把它描述成
裁判已有的 XY 扣分条件。PDF 写明 200×100 米，并未给出同样的
坐标端点；比赛方若指定不同边框，必须重新核对，不能用人物插件
活动范围或渲染平面尺寸自动扩张飞行区。官方人物、地图、裁判和传感器
均未修改。边缘人物仍通过场内观察点跟踪，不把其坐标夹成虚假上报。

停止前的六机全段估计范围和官方结果见
`artifacts/boundary_fix_20261011/before.json`。其中范围包含比赛结束后
到停止节点之间的数据；不能用该累计数推算比赛期间越界时长。

## 修改

- 新增纯规则模块 `flight_boundary.py`，统一管理器、agent 和启动预检。
  拒绝旧环境变量把边界放大，正常航点保留 2 米内缩。
- 搜索改为城市范围内 390 格，不再派 570 格传感器存储区。末行、末列
  不足 7 米时，中心按实际剩余宽度计算，界外点不能映射到这类残格。
- 边缘搜索点从场内 8.5 米观察环选择，角落兼顾两侧余量。
  未收到处理过的真实图像仍不会记作观察完成。
- A* 和 agent 局部栅格保护使用导航边界掩码，不能绕墙绕到界外。
  原始 SLAM、共享占用、视觉 LOS 保持传感器内容，不伪造边界障碍测量。
- 向外速度满足 `v*0.6 + v²/(2*1.2) <= 距边界-2`，替代整个 8 米边缘
  带统一限到 0.5m/s。保持向内及沿边运动；最终输出、脱困和加速度
  限制之后仍检查边界；裁掉分量改变方向时重新检查实际方向的激光。
- 越界回收也经过雷达和栅格约束，不再假定界外无障碍。

## 验证及限制

620 项回归通过，脚本语法、差异格式、正式预检通过。新增覆盖旧边界
环境覆盖、残格、六区完整性、A* 界外绕行、传感器不被掩码污染、四边
制动预算、回收不能覆盖障碍停车，以及最终位置输出。

搜索排序回放改用实际城市范围和 x=120 的东侧前沿。新路线东三分区
总路程下降；北东分区完整路程增加 27 米，但到 x=120 提前 154 米。
因此不再声称每个分区的完整路线都更短。未减少待搜索格来通过覆盖测试。

离线制动公式不能证明 PX4 的真实响应。提交后的 GUI 整场仍需验证
真实位置、估计位置、碰撞、漏检和六人消除时间；不得拿 620 项测试或
旧版本 6/6 代替本批运行结果。约 180 秒目标、三轮复验及雕塑识别仍未完成。
