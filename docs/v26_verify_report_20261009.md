## 0.1 关键语义澄清（本报告纠错核心）

**裁判计分源码**（`score_cal.py`，XT/Do 运行版与 coordination 版一致）：

```python
def _progress_score():
    return (find_finish * 50 + target_finish * 100
            - sensor_cost * 3e-3 - uav_loss_count * uav_loss_penalty)
```

- `find_finish`：`find_actors` 中被移除（进入"确认期/find"）的 **actor 数**。**不是消除数**。每订阅到一次满足门限的正确播报并计入 `count_flag` 即触发 `find actor_N`。
- `target_finish`：`_delete_actor` 移除 `left_actors` 成功的 **真正消除数**。消除唯一标志 = 日志里 `actor_N is OK`。
- 末端全清：`_finish('Mission finished', 2580 - elapsed - ...)`。
- **`track×80` 已于 2026-10-09 [MERGED] 从计分中删除**（`score / _progress_score` 注释：track×80 被远端回滚）。

**两轮实际读数**：

| 轮 | FINAL score | find_finish | `actor.. is OK` | track×80 | sensor_cost 折算 | 反推计分 |
|---|---|---|---|---|---|---|
| v24 (06:43 运行实) | **254.9** | 2 | **0** | **启用** | 5.1 分 (cost≈1700) | 2×50 + 2×80 − 5.1 = **254.9** ✓ |
| v26 (09:51 运行新) | **94.9** | 2 | **0** | **已删** | 5.1 分 (cost≈1700) | 2×50 + 0 − 5.1 = **94.9** ✓ |

`v21=464.9=3 find×50+4 track×80−5.1` 与 `v24`、`v26` 三式全部自洽 → **证实**：v24/v26 真实消除（`target_finish`/`is OK`）**均为 0**，二者 `find_finish` 也相同（=2）。

## 4. 纠正后的总体结论

1. **计分口径勘误（本榜最重要）**：v26 score=94.9 与 v23=254.9 的 160 分差来自 **track×80 被删除**，并非 v26 表现退化。**用 find_finish、真消除这两个同口径指标对比：v24=2/0、v26=2/0，完全持平**。此前"大幅下降坏局"的定性作废。
2. **修复项本身均有效**：崩溃 0（指标6）、巡航提速 3.0（指标2）、首击即派（指标5）、红线/uav_loss/START_OCCUPIED 0（指标10）——4 项结构修复确认。
3. **真实短板**：
   - 搜索覆盖不足（find 只 2/6，东/北区未调达）——受近障困局拖累；
   - 消除链路断裂：追踪贴不进 9.5m 播报闸门 + YOLO 误差大 → 15s 确认凑不满 → **真消除仍 0**（与历史所有轮次一致）。

## 5. 下一步建议（按优先级）

1. **近障脱离**：近障触发 3s 未脱离 → 强制升 8m 越障 / 切线绕行，打断转向死循环，使搜索推进到 x>60。
