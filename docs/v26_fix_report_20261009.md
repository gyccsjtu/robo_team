## 二、根因深度分析（三链路）

### 2.1 首击即派死结（本次 v26 代码修复）

**证据**：v24 日志 5 次 `GATE_DBG white range=11.5 gate_live=False`。飞机观测到 white 但被桥闸门（≤9.5m 才播报）拦截，说明**从未有飞机真正贴近到 9.5m 内**。

**根因**：目标一经检测，manager 走两条派机链路：
- `_dispatch_pending_targets`（周期兜底）——**门槛已放宽到 60m**（v25 修复 4，实测就绪）
- `_dispatch_tracker`（首击即派）——**残留门槛 `DETECT_RADIUS - DISPATCH_MARGIN` = 10 - 2 = 8m**

首击时检测机自身正在执行搜索任务（内存中 `_search_going=True` 非空闲），"最近空闲机"往往落在 8~60m 区间，被 8m 门槛拦截 → 白白等待下一个调度周期才派机。翼楼观测窗口溜走。

**本次修复**（`swarm_manager.py` `_dispatch_tracker`）：
```python
# v26：派机门槛统一为 DISPATCH_FAR_LIMIT（与 _dispatch_pending_targets 一致）。
# 旧值 DETECT_RADIUS-DISPATCH_MARGIN=8m 只在最近空闲机<8m 时首击即派，
# 检测机自身不空闲时第二近空闲机常落 8~60m 被拦，整轮推迟一个周期。
_disp_limit = float(os.environ.get("DISPATCH_FAR_LIMIT", "60.0"))
```
与 `run_match.sh` 的 `DISPATCH_FAR_LIMIT=60.0` 完全对齐。接近后无观测由 `TRACK_CONFIRM_TIMEOUT` 超时释放兜底，不浪费机。

### 2.2 搜索格覆盖不足（v25 已修 + 本轮验证）

**证据**：v24 全部分配 x∈[-44.5, 39.5]，y∈[-54.5, -12.5]；东区(x>60)/北区(y>0) 的 actor_1/2/3 活动区零派格，5min 场地覆盖率仅 17%。

**三因叠加**：
1. **巡航速度**：旧实现搜索段峰值仅 1.7m/s（POS_KP 控制残差），5min 飞不出西区 → v25 修复：`SEARCH_CRUISE_SPEED=3.0, SEARCH_DECEL_M=2.0` 恒速巡航。
2. **出生区锁定**：前 90s 全队挤在 spawn 西区近格（early_close_bonus）→ v25 修复：`EARLY_PHASE_SEC=90→30`。
3. **分配公平性**：`W_ZONE` 责任区 0.5 软约束在格收益前被压过 → v25 维持 Voronoi 分区 + `ALLOC_PERIOD=1.0` 更密集拍卖。

**v26 验证项**：提速 + 早散开 + 首击即派三者联动下，搜索格应推进至 x>60 / y>0。
