# 为什么不能全部消除 Actor —— 四层断点诊断与修复（v18）

日期：2026-10-07 深夜 | 依据：logs_20261007_213201（v17 尸检）+ 两轮验证场

## 裁判消除判据（官方 score_cal.py）
同时满足：相邻播报间隔 ≤1s + 误差 <1m + 从首次有效播报起连续 15s。
任一违规 `_reset_detection` 清零重来。actor 被无人机 <20m 且速度>1m/s 持续 2s 会逃跑。

## 四层断点（按致命度）

### 断点 1（P0）：v16.1 引入的 NameError 回归 —— 贴脸跟随全失效
- v16.1 重排到圈分支时弄丢 `target_id = getattr(self.assignment,'target_id',None)`，
  但 `_want_target = target_id if ...` 仍在使用 → NameError。
- v17 实测：agent_3/4 **恰好在到圈贴脸时刻**（sim=250.8s/265.2s）开始崩溃，
  7420/6860 次 → 贴脸跟随中断 → actor_0 播报窗口 win=10s < 15s 永远凑不满。
- 这就是「tracking success 却无法消除」的直接原因。
- **修复**：swarm_agent.py 补回赋值行。

### 断点 2（P0）：EKF 雪崩熔断 → LAND → 落地死锁
- agent_2(127.5s)/agent_1(140.3s)/agent_0(274.7s) 被「累计 50 拍不可信 → 强制 LAND」。
- `_ekf_frozen` 全文件**永不清除**（单程票）→ 5/6 架趴地到比赛结束
  （终态 z=0.12~0.30m）→ 相机看地面 → 0 检测 0 播报。
- **修复**：`_send_vel` 熔断检查之前插入恢复逻辑：触地 z<0.35 + EKF 恢复可信
  → 清熔断状态 + 重新走垂直爬升门复飞（再雪崩再熔断，安全闭环）。

### 断点 3（P0）：Fix D 闩锁拦死复飞爬升
- agent_1 432s 实证：趴地复飞 vz=0.6 但 EKF z 病态 |Δz|=0.22<0.30 → 闩锁 vz≤0，
  解锁条件（alt_error<0.3 or moved）在 EKF 病态下永不满足 → 永远爬不起来。
- **修复**：闩锁触发加 `local_z>1.5` 地面豁免；闩锁保持分支加 `local_z<1.5` 自动解除。

### 断点 4（P0）：`wx, wy = self.world_xy` 先 unpack 后判 None
- EKF 雪崩期 world_xy 返回 None → TypeError 主循环反复崩溃
  （agent_0 复飞爬升被打断，加剧熔断-复飞循环）。
- **修复**：4 处改为先判 None 再 unpack（1449/3088/3239/3268 行）。

## 残余问题（下一轮迭代）

1. **播报误差 5~11m（最大瓶颈）**：far_dist 大量被拒（9~20 次/actor）。
   贴脸 2m 圈 ed≈0.95m 才勉强达标，大量播报来自未贴脸的中远距检测。
   → 下一步：只有贴脸圈（<3m）内才允许播报 / 提高贴脸收敛速度。
2. **agent_5 熔断-复飞循环**：EKF 持续雪崩（3.8s 一轮熔断），趴地收场。
   → EKF 雪崩根因在 PX4 SITL 多机 GPS/气压仿真，软件层只能兜底。
3. **green/brown tag 零覆盖**：搜索铺开仍不足，部分 actor 从未被检测。
4. **white avg_gap=1.45s > 1s**：检测帧率间歇掉线，15s streak 凑不满。

## 结论
「不能全部消除」不是单一 bug，而是**四层断点叠加**：找到的贴不了脸（NameError），
没趴地的被熔断趴地（LAND 死锁），趴地的爬不起来（闩锁+unpack 崩溃）。
四层全修后 find_finish 1→3。要 6/6 全消除，还需解决播报误差（贴脸质量）与
EKF 雪崩根因（PX4 层）。
