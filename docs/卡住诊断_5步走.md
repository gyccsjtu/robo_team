## 1. 卡死六类速查表（一眼对号入座）

| 序号 | 在 agent 日志里的关键字 | 含义 | 根因排查 |
|---|---|---|---|
| ① | `位置估计不可信 … 累计 N 拍` | EKF 估计速度 > 7.2 m/s，**自动悬停等收敛** | 看 PX4 `/mavros/local_position/pose` 是否跳变 → 跳就是 EKF，没跳就是 `EST_V_RATIO` 太紧 |
| ② | `已抵达格中心 … 派搜到此为止` + 后续没 `派搜索` | 到达但**没新格可派**（全队都在追 / 全图 COVERED 未到期） | 看 manager 的 `已重新开放 N 个 COVERED`，N=0 就说明没格可派 |
| ③ | `路径规划失败` / `规划失败` 反复出现 | A* 找不到路（被困建筑内 / 起点在障碍格） | 看当前 world_xy 是否在 `grid` 自由栅格外 |
| ④ | `释放追踪机` + 该机 agent 日志无新派遣 | 被派去追目标后**目标已删除**（官方重置 15s 未确认） | 看 `detection_to_official` 是否还在喂 `/find_actor_N` |
| ⑤ | `休跑中` / `OFFBOARD 丢失` / `arm=False` | 没拿到 arm 或 offboard 控制权 | 看 `06_..._.log` 的 `[arm]` `[offboard]` 关键字 |
| ⑥ | 啥都没有（agent 日志静默） | 进程崩了 / 节点死了 | `ps aux | grep swarm_agent_N` 看进程在不在 |

## 2. 按编号走的诊断流程

### 2.1 ①类：EKF 估计不可信
```bash
grep -E "位置估计不可信|_est_trustworthy|EST_GUARD" $LOG/06_swarm_agent_<卡住机>.log | tail -10
# 同时查 PX4 真值
rostopic echo -n 1 /typhoon_h480_<N>/mavros/local_position/pose/velocity | head
```
- 若速度真 > 6 m/s：PX4 EKF 异常，**重启 mavros**：
  ```bash
  rosnode kill /typhoon_h480_<N>/mavros
  # 然后由 run_match.sh 之外手动重启，或整场重启
  ```
- 若 PX4 速度正常（< 1 m/s）但日志说不可信：`EST_V_RATIO` 设得太紧，
  ```bash
  # 临时放宽（赛事环境变量）
  export EST_V_RATIO=1.5   # 默认 1.2
  ```

### 2.2 ②类：到格中心但无新格
```bash
# 关键：看 manager 是否给了新任务
grep -E "派搜索|派追踪|无可派|无空闲机|active_leases" $LOG/04_swarm_manager.log | tail -30

# 看所有格子状态统计
grep -E "STATE_FREE|STATE_COVERED|STATE_ASSIGNED|已重新开放" $LOG/04_swarm_manager.log | tail -20
```
- 若 `无空闲机` 出现 > 3 次：**全队都在追**，没有"搜"的人 → 触发
  `REOPEN_WHEN_TRACKING=1`（默认开），30s 后强制 reopen。
- 若 30s 后还是没新格 → 看 `REV_COVER_AGE`：
  ```bash
  grep "REV_COVER_AGE" ~/桌面/RoboCup_Team/run_match.sh
  ```
  默认 30s，若发现环境变量被改成更大值，改回 30。

### 2.3 ③类：A* 规划失败
```bash
grep -E "规划失败|A\*|plan_fail" $LOG/06_swarm_agent_<N>.log | tail -10
# 现场查当前坐标
rostopic echo -n 1 /typhoon_h480_<N>/mavros/local_position/pose | grep -E "x:|y:"
```
- 若坐标在建筑内：飞机**被困**了 → 需要换地图或扩大 ESDF 膨胀半径。
- 若坐标正常但 A* 失败 2s 冷却反复：环境有**未登记障碍**，人工遥控绕过。

### 2.4 ④类：追的目标被删了
```bash
# 查目标的发现/确认/重置
grep -E "已被官方重置|官方首次发现|release|目标.*删除" $LOG/04_swarm_manager.log | tail -20
# 查裁判是否还在发 find_actor
rostopic echo /find_actor_0 -n 1 2>&1 | head -10
```
- 若裁判侧已删：等 30s reopen 自动起搜。
- 若裁判还在发但我们 `detection_to_official` 没喂：检查
  `09_detection_to_official.log` 是否在更新。

### 2.5 ⑤类：OFFBOARD/arm 丢失
```bash
grep -E "offboard|arm|armed|set_mode" $LOG/06_swarm_agent_<N>.log | tail -15
```
- `set_mode OFFBOARD` 失败 → 飞控需要先在 `AUTO.LOITER`（或 `POSCTL`），
  且起飞高度 > 0.3m。
- `arming` 失败 → 检查 PX4 `COM_RC_IN_MODE` / 遥控器。

### 2.6 ⑥类：进程死了
```bash
ps aux | grep swarm_agent_<N> | grep -v grep
tail -n 30 $LOG/06_swarm_agent_<N>.log
```
- 若进程不在 → 拉起来：
  ```bash
  bash ~/桌面/RoboCup_Team/run_match.sh restart_swarm   # 若有该子命令
  # 或单独手动：
  rosrun robocup_swarm swarm_agent.py _uav_id:=typhoon_h480_<N> &
  ```

## 6. 常见误判：以为卡住其实没卡

| 现象 | 其实是在做什么 |
|---|---|
| 刚到格中心 + 原地"停"0.5~3s | 正常：释放租约 → 拍卖 → 拿新格 |
| 追目标时在某点绕圈 5~10s | 正常：`_fly_orbit` 圆周运动（半径 6m、角速度 0.13 rad/s） |
| 飞过路径中"卡"1~2s | 正常：A* 重规划窗口（被前机挡） |
| 30s 周期性停顿 | 正常：`REV_COVER_AGE=30` 周期 reopen |

只有**>20s 完全不动**才进入本诊断。
