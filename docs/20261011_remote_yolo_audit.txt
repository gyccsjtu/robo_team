模型与代码检查
- v3_clean 是五类 red/green/blue/white/brown，类序与主库一致；没有雕塑类。
- 系统 Python 3.8、torch 2.4.1 CPU 实际加载并推理成功。
- 单线程、无六机竞争、同一原图预热后约 18 ms；不能外推六机运行帧率。
- 配套 yolo11n_person.pt 实际含 COCO 80 类，不是演员/雕塑专用二分类器。
- 配套 perception_real.py 主路径等待并调用 /gazebo/get_link_state 获得相机
  位姿，不可整套搬入本队的 MAVROS 位姿比赛路径。
- 配套发布判决仍有运动/静止资格；静止例外按颜色/任务和配置分支。
  整套迁移会重新带入静止真人被过滤的风险。
- 配套 target_report 仍是旧单条字段接口；不能覆盖本队来源、图像时间、实例
  身份和 report_ok 等新契约。

后续解决路线（未声称实现或验收）
1. 保留生产五色检测器作为对照。优先验证独立的演员/雕塑外观复核，避免
   直接用召回退化的六类权重覆盖全部识别；额外推理负载必须实测。
2. 补实战误检雕塑、脚手架/消防栓背景，与绿色/蓝色/白色困难真人；含静止、
   移动、远处、小框、遮挡、截断，以及真人紧邻雕塑。混合画面不得空标签。
3. 复核只对同一图像实例生效；邻近不是同一物体。不能用跨模型原始置信度
   直接相减当概率，也不能简单降低 IoU 门限掩盖框定义差异。
4. 连续新帧支持的强雕塑证据可排除该实例，模糊结果短时补看。静止不是
   雕塑证据；不使用地图坐标黑名单；失败候选不能长期占用颜色槽/飞机。
5. 若继续六类单模型训练，保留原真人数据，新增困难真人训练样本、人工校核
   演员/雕塑边界，比较冻结部分特征/较小学习率等受控实验，避免遗忘。
   验证集漏检图只能用于诊断/选型，不能直接加入训练后继续声称独立验证；
   修标签要留版本并重跑新旧模型，新采集序列按布局/整段划分。
6. 验收看每色召回、演员被错抑制数、雕塑持续派机数、连续报告间隔和六机
   推理负载。保持主模型不能自动保证整条链召回不降；复核同样可能误杀。
   最后才是多轮官方比赛，不能用单张不误报声称完全解决或 6/6。
