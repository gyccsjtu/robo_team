## 4 官方两个缺陷（已判定：**不影响我们** ⇒ 不反馈）

> 2026-09-29 结论：用户问「如果不影响我们就不告诉官方了」⇒ 逐条验证影响面后确认

> 下面保留事实记录，供后续需要时引用。

### 4.1 `map_generator.py` fallback 分支产出**空 world**

```python
content = open("base"+str(map_num)+".world", 'r')
...
lines = content.readlines()          # ① 首次读完
center_list, find_solution = create_point()
while (not find_solution) and count_loop < 10:
    center_list, find_solution = create_point()
if count_loop >= 10:
    lines = content.readlines()      # ② 文件对象已耗尽 ⇒ 恒返回 []
    f.writelines(lines)              # ⇒ house.world 被写成 0 字节
```

`create_point()` 连续失败 10 次即触发。**本机 8 次生成里中 2 次（25%）**：
r1、r5 的 `robocup.world` = **0 字节**，而 `obstacle.txt` 仍写出 3600 行
（基于最后一次失败的中心点）⇒ **world 与障碍表不一致**。

⇒ 后果：比赛若撞上，Gazebo 加载空世界，全场无建筑，任务无意义。
⇒ 建议：组委会修 fallback 分支（把 `content` 改成 `open(...).readlines()` 每次重读）；
我们侧在 `fly_rand.sh` 里已加 `[ -s "$WORLD" ]` 非空检查。

### 4.2 建筑被放在**无人机起飞点上**

`create_point()` 只保证 13 栋建筑**彼此**不重叠（判据 `size_box_judge` +3 m 余量），
**完全不检查与 6 个起飞点 `(0,±3)/(3,±3)` 的距离**；而 `create_human_point()` 却有
`uav_start_clearance = 8.0` 的行人避让。**建筑放置缺同样的检查。**

实测：本机 6 张图里 2 张（r4、r6）、VM 6 张里 1 张（try4）把 30×25 的
`fast_food_93` 盖在起飞点上（如框 `[-11,19]×[1.5,26.5]` 含 `(0,3)`）⇒ **3/12 = 25%**。

⇒ 后果：飞机**生在楼里**。楼高 7.86 m > 6 m 限高 ⇒ 既飞不出去也压不过顶，
**换任何算法都无解**，且必然产生碰撞扣分。
⇒ 我侧缓解：A\* 的 `nearest_free()` 会自动吸附到楼外（实测吸附到 `(0,-2)`），
但现实中 PX4 出生点在楼内，起飞动作本身就会撞。
⇒ 建议：组委会在 `create_point()` 里加与 `uav_takeoff_points` 的距离检查。

### 8.3 🔴 Kimi 没发现的那条：**细杆的 `blocked` 漏加 margin**（真缺陷）

`diag_seg.py` 把第 6 组那条路径逐段拆开，抓到**判定不一致的确切位置**：

```
段1 (37.00,-17.00)->(7.00,2.00) len=35.51
     seg_clear(0.5m步长)=True   ← A* 认为能走
     0.25m 细扫      =False   ← 实际穿过了 blocked
     0.05m 细扫   blocked=(7.76,1.52)
```

顺着这个点回到 `Grid.__init__`，发现**细杆分支根本没加 margin**：

```python
# 建筑：外扩 margin ✓
for (nm, cx, cy, hx, hy, yaw) in buildings:
    self._fill_rect(cx - hx - margin, ...)          # ← 有 margin
    self._fill_rect(cx - hx, ..., core=True)
# 细杆：两次调用**参数完全相同** ⇒ blocked == core ✗
for (px, py) in poles:
    self._fill_rect(px - pole_r, py - pole_r, px + pole_r, py + pole_r)
    self._fill_rect(px - pole_r, py - pole_r, px + pole_r, py + pole_r, core=True)
# 官方点阵：有 margin ✓
for (px, py) in self.points:
    self._fill_rect(px - h - margin, ..., core=True)
    self._fill_rect(px - h - margin - margin, ...)
```

⇒ 建筑侧干净（≥2.24 m），证明 `margin` 参数本身没问题，**就是细杆分支少写了两个 `margin`**。

**影响面（重要，别夸大）**：
