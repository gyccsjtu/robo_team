# 变更日志 2026-10-04：侧向守门全分辨率化（修"长墙掠射漏检"）

## 背景

撞墙排查确认头号嫌疑为代码自登记的「长墙掠射漏检」（radar_avoid.py
原 207-215 / 1277-1290 / 1321-1333 三段注释，README §11 此前**未**
真正登记——注释声称"已登记 README"实为不实）：

- 飞机平行贴长墙飞 ⇒ 激光掠射几乎无回波（512 束实测仅 2~4 束命中）
- 经 GAP_STRIDE 抽稀后可能一束不剩 ⇒ 侧向守门 left/right_min=None
  ⇒ 整段不动作 ⇒ 以 0.5m 级余量贴墙飞（真实地图 随机4 净空 0.466m）

## 改动（radar_avoid.py，均不触碰 GAP_DEV_MAX）

1. **新增 `lateral_mins_fullres()`**：全分辨率（stride=1）统计行进方向
   左右最近障碍横向距离。投影链与 `scan_to_obstacles` 逐行一致，
   过滤语义与守门原循环一致（qd>INFLUENCE / |lat|<1e-6 / fwd<=-|lat|），
   结果是抽稀统计的**超集**——只会更保守，不会漏掉原本可见的障碍。
2. **新增 `lateral_guard_shift()`**：守门动作逻辑从 `subgoal_from_scan`
   内联代码原样抽出为纯函数（逐行等价，未改语义）。
3. **守门输入升级**：`subgoal_from_scan` 的守门改为
   「obs 循环 ∪ 全分辨率统计」取更小者合并；
   行进单位方向 ufx/ufy 移出 `if obs:` 判定。
4. **obs 整帧为空时守门照常运行**（新增 else 分支）：掠射场景抽稀后
   0 点恰恰最需要守门，旧代码在此整段跳过——这正是本次修复的核心。
5. 两处历史注释追加"已修复"标注；README §11 第 7 条正式登记（留档）。

# 变更日志 2026-10-04（二）：修「单机切不进 OFFBOARD」——设定点心跳线程秒死

## 结论先说

**根因不是环境、不是 PX4 参数、不是 EKF，是一个纯代码竞态**：
设定点心跳线程在第一轮就抛 `AttributeError` 当场死亡，导致全脚本**唯一**
的 `setpoint_position/local` 发布点消失 ⇒ MAVROS 永不发
`OFFBOARD_CONTROL_MODE` ⇒ PX4 判定 `offboard_control_signal_lost = True`
⇒ `main_state_transition(OFFBOARD)` 返回 DENIED。

## 证据链（VM 实测，修复前）

```
# rf_online.log（线程死亡）
Exception in thread Thread-8:
  File "radar_avoid.py", line 1763, in _sp_loop
    p = self.sp
AttributeError: 'RadarPilot' object has no attribute 'sp'

# px4why.log（PX4 侧表现）
INFO  [commander] Armed by external command
[WARN] CMD: Unexpected command 176, result 1      <- DO_SET_MODE 被 TEMPORARILY_REJECTED
INFO  [commander] Disarmed by auto preflight disarming
```

代码层面：`self.sp` **只在 `set_sp()` 里首次赋值**，而
`__init__` 里 `self._th.start()` 在 `set_sp()` 之前执行；心跳线程第一轮
`p = self.sp` 必然抛异常。**该线程没有任何 try/except ⇒ 静默死亡**。

PX4 判据（源码已核）：`src/modules/commander/state_machine_helper.cpp`
`MAIN_STATE_OFFBOARD` 分支只认 `!status_flags.offboard_control_signal_lost`，
而该标志由 `Commander.cpp` 依据 `offboard_control_mode` uORB 话题刷新
（`_offboard_control_mode_sub`），MAVROS 只在**有设定点流**时才发它。

## 改动（radar_avoid.py 四处）

1. **`__init__` 里先 `self.sp = None` / `self._sp_sent = 0`，再启动线程**，
   并打印线程启动日志（消除竞态 + 让"线程起来了"可被日志证实）。
2. **`_sp_loop` 整体兜异常**：任何单帧异常只记日志、线程继续。
   心跳线程的"静默死亡"是本事故的唯一传播路径，必须堵死。
   新增首个 setpoint 发布成功时的一次性日志。
3. **`set_failsafe_params()` 升级为 pull → set → get 读回验证**
   （对齐队友 codex 分支的 `fcu_configuration`）：
   `NAV_RCL_ACT=0`、`COM_RCL_EXCEPT=4`、`NAV_DLL_ACT=0`；
   3 轮读回不一致直接返回 False 拒绝起飞（原实现只看 `param/set` 返回值）。
4. **`takeoff()` 重排为队友已验证时序**，且顺序改为
   **先 OFFBOARD、后 arm**（旧序先 arm 会先启动 PX4 地面自动上锁计时
   `COM_DISARM_PRFLT=10s`，OFFBOARD 重试超过 10s 就被踢掉）：
   ① 连续 40 次（20Hz = 2s）|local_z| < 1.5 判 EKF 稳定；
   ② OFFBOARD 持续重试 90s（回读 `state.mode`，不信 `mode_sent`）；
   ③ arm 持续重试 30s；
   并在 ② 前显式检查 `_sp_sent > 0`，心跳没发过帧就直接点名报错。
